# 未央黑客松 飞书选手服务机器人

读取「活动报名」多维表格，维护一个选手数据库（一人一个 ID），选手私聊机器人发送「验证」即可通过飞书账号手机号完成授权，验证通过后自动拉入所有配置的交流群；支持定时自动同步与补拉。

## 架构

```
bot/
  main.py            入口：WebSocket 长连接 + APScheduler 定时任务
  core/
    config.py        .env 配置
    lark_client.py   飞书 API 封装（发消息/读手机号/拉群）
    base_store.py    多维表格读写（cli / sdk 双后端）
    registry.py      插件注册器（指令 / 卡片回调 / 定时任务）
    event_bus.py     事件路由
    card_kit.py      卡片模板
  modules/           功能插件（导入即注册，可插拔扩展）
    sync/            报名表 -> 选手库 同步（手机号去重、队友拆分、队伍关系）+ 管理员识别
    auth/            验证授权（读飞书手机号 -> 比对选手库 -> 绑定 open_id）
    group/           拉群 / 补拉（群配置表驱动、拉群记录留痕、群成员实时数据幂等）
    profile/         个人中心（选手 ID / 队伍 / 项目提交状态）
    score/           积分（骨架）
    activity/        活跃度（骨架）
    ticket/          票务（骨架）
scripts/
  init_base.py       全量同步脚本
  backfill.py        手动补拉脚本
  describe_fields.py 给 Base 所有表字段写描述注释（幂等；Link 字段 API 不支持，见脚本内文档）
```

扩展新功能：在 `bot/modules/` 下新建目录，用 `@REGISTRY.command("指令名")`、`@REGISTRY.on_card(...)`、`@REGISTRY.job(...)` 注册即可，无需改核心代码。

## 选手数据库（Base `QD2ubyLMraQlNrsA3eicyrwhngh`）

| 表 | 用途 |
|---|---|
| 选手表 | 一人一条记录，`选手ID`（WY01-0001）唯一；手机号为去重键；`发言数` 由机器人自动累计 |
| 队伍表 | 仅「是否预组队=是」（明确组队成功）的报名记录入表，队长/队友 link 到选手表 |
| 群配置表 | 机器人要拉的群清单（群名 / chat_id / 启用） |
| 拉群记录表 | 每次拉群留痕（审计；是否已在群里以飞书群成员实时数据为准） |
| 项目表 | 参赛项目（项目ID/名称/介绍/队伍/成员/仓库与演示链接/票数） |
| 投票表 | 决赛投票流水（投票人 → 项目），一人一票由机器人校验 |
| 积分表 / 活跃度表 | 扩展功能流水表（活跃度表由群发言监控自动写入） |

去重规则：手机号归一化后必须通过大陆手机号格式校验（`1[3-9]` 开头 11 位），无效手机号直接跳过不同步；同一人出现在主报名人和多个队伍的队友栏时只保留一个选手 ID，审核状态取最优（任一队伍通过即通过）。

## 快速开始

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env          # 填入 FEISHU_APP_ID / FEISHU_APP_SECRET
.venv/bin/python scripts/init_base.py   # 全量同步（也可跳过，机器人启动后会自动同步）
.venv/bin/python -m bot.main            # 启动机器人
```

## 飞书开发者后台配置清单

1. 创建企业自建应用，启用「机器人」能力。
2. 开通权限：`im:message:send_as_bot`、`im:message:readonly`、`im:chat:read`、`im:chat.members:write_only`、`im:chat.members:read`、`bitable:app`、`contact:user.base:readonly`、**获取用户手机号**（`contact:user.employee_id:readonly` 所属的手机号读取权限）、`application:application:self_manage`（管理员识别，或 `admin:app.info:readonly`）。
3. 事件与回调：订阅方式选择「**使用长连接接收事件**」，订阅 `im.message.receive_v1`；如需卡片交互，开启回调配置。
4. 把「活动报名」Base 和「选手数据库」Base 添加应用为**协作者**（可编辑）。
5. 应用可用范围加入需要验证的选手。
6. 把应用的 App ID / App Secret 填入 `.env`。

## 机器人指令

| 指令 | 说明 |
|---|---|
| `验证` / `授权` / `验证身份` | 私聊机器人，读取飞书账号手机号（外部用户填表单：手机号+vx号）与选手库比对，绑定 open_id。**验证=绑定身份，与审核解耦**：审核未通过也会绑定成功，审核通过后自动拉群 |
| `个人中心` / `我的` | 我的选手 ID、验证/审核状态、队伍与队友、项目提交状态（帮助卡也有「个人中心」按钮） |
| `活跃` / `活跃度` | 查看群发言活跃度排行（机器人自动监控群发言累计） |
| `投票` | 决赛投票：机器人回复项目列表卡片，点按钮投票，一人一票 |
| `票数` / `票榜` | 查看当前票榜 |
| `开票` / `关票` | 开关投票通道（管理员） |
| `同步` | 手动触发一次报名表同步 |
| `补拉` | 把所有已验证选手补进缺失的群（管理员；以群成员实时数据为准，新增群自动覆盖） |
| `管理员` | 查看当前管理员名单与来源 |
| 其他任意消息 | 回复帮助卡片（含快捷按钮：验证 / 投票 / 活跃度 / 票榜，点按钮即触发） |

## 卡片

全部使用**新版卡片 JSON 2.0**（`schema: "2.0"`）：帮助卡片带快捷操作按钮（behaviors callback），验证表单用 form 容器 + 提交按钮（`form_action_type: "submit"`），投票卡片每个项目一个回调按钮。回调事件仍为 `card.action.trigger`，按钮值在 `action.value`、表单值在 `action.form_value`。要求飞书客户端 7.20+（低版本只显示标题）。

## 管理员识别

管理员 = **飞书开发者后台的应用协作者**（owner / administrator 等）。机器人启动时调「获取应用协作者」API 拉取名单，之后每 10 分钟自动刷新；需要权限 `application:application:self_manage` 或 `admin:app.info:readonly`（任一）。`.env` 的 `ADMIN_OPEN_IDS` 作为兜底（API 失败时仍可用）。

## 验证与审核的关系

- **验证**：确认「这个飞书账号 = 报名表里的某个人」，成功即绑定 open_id、标记已验证。
- **审核状态**：只由报名表同步刷新（审核状态取最优：任一队伍通过即通过）。
- **拉群**：验证成功且审核通过 → 立即拉群；验证成功但未审核 → 等审核通过后由「审核通过补拉」定时任务（每 30 分钟）自动拉群，无需重新验证。

## 活跃度监控

机器人在群内收到每条消息（含非文本）时，若发言者是已验证选手，则选手表「发言数」+1 并在活跃度表写一条「发言」流水。`活跃` 指令查看 Top 10 排行，管理员额外可见总发言数。

## 群配置

在「选手数据库 → 群配置表」添加行：群名、`chat_id`（oc_ 开头，可让机器人进群后通过 API 查询）、勾选「启用」。验证通过的用户会被拉入所有启用中的群。

**新增群怎么办**：不需要任何手动操作。机器人默认每 30 分钟（`BACKFILL_INTERVAL_MINUTES`，设 0 禁用）自动补拉一次——按群成员实时数据找出还没进新群的已验证选手并拉入；也可以随时让管理员发「补拉」立即执行。是否已在群里完全以飞书群成员列表为准，不依赖任何本地状态字段。
